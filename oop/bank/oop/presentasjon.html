IT2 — Bank-oppgaven, del 2

Der vi slapp

Forrige time lagde vi en bank med dictionaries og funksjoner.


kunder = {
    "1001": {"navn": "Ola Nordmann", "saldo": 1500},
    "1002": {"navn": "Kari Nordmann", "saldo": 3200},
}

def sett_inn(kunder, kontonummer, belop):
    kunder[kontonummer]["saldo"] += belop

sett_inn(kunder, "1001", 500)

Den fungerer! Men ... 🤔

Diskuter to og to

  1. Hvor mange ganger skrev du kunder[kontonummer]["saldo"]?
  2. Hva skjer om du skriver "sado" i stedet for "saldo"? Når oppdager du feilen?
  3. Hvor mange funksjoner måtte få kunder som parameter?
  4. Hva hindrer noen i å skrive kunder["1001"]["saldo"] = 1000000?
  5. Vi vil legge til transaksjonshistorikk. Hvor må koden endres?
Typiske svar: 1) Overalt — lang og lite lesbar kode. 2) KeyError først når akkurat den linjen kjøres. VS Code kan ikke hjelpe, det er bare tekst. 3) Nesten alle — og de trenger kontonummer i tillegg. 4) Ingenting. Reglene ligger i funksjonene, men ingen tvinger oss til å bruke dem. 5) opprett_kunde, JSON-fila, sett_inn, ta_ut, overfor ... endringene sprer seg. Bonus: Hvor i koden står det hva en "kunde" ER? Ingen steder.

Steg 2: Metoder

Vi flytter funksjonene inn i klassen.


class Konto:
    def __init__(self, kontonummer, navn, saldo=0):
        self.kontonummer = kontonummer
        self.navn = navn
        self.saldo = saldo

    def sett_inn(self, belop):
        if belop <= 0:
            print("Beløpet må være større enn 0.")
            return
        self.saldo += belop
        print(f"Satte inn {belop} kr.")

ola = Konto("1001", "Ola Nordmann", 1500)
ola.sett_inn(500)

Vi slipper å sende med kunder og kontonummer — kontoen vet hvem den er.

Hva er egentlig self?


ola.sett_inn(500)

... betyr egentlig:


Konto.sett_inn(ola, 500)

Python sender automatisk objektet foran punktumet inn som self.

Når kari.sett_inn(500) kjøres, er self Karis konto.

Metoder kan bruke hverandre


    def overfor_til(self, annen_konto, belop):
        if belop <= 0:
            print("Beløpet må være større enn 0.")
            return
        if belop > self.saldo:
            print("Det er ikke nok penger på kontoen.")
            return
        self.ta_ut(belop)
        annen_konto.sett_inn(belop)
        

ola.overfor_til(kari, 1000)

Et objekt kan ta imot et annet objekt som parameter.

Steg 3: Mange kontoer

Konto = én konto. Men hvem holder styr på alle?


class Bank:
    def __init__(self, filsti):
        self.filsti = filsti
        self.kontoer = {}  # kontonummer -> Konto-objekt
        self.les_fra_fil()

    def finn_konto(self, kontonummer):
        if kontonummer not in self.kontoer:
            return None
        return self.kontoer[kontonummer]

Objekter og JSON

JSON kan lagre tekst, tall, lister og dictionaries — ikke våre egne objekter.

kunder.json → json.load → dictionary → Konto(...) → Konto-objekter

kunder.json ← json.dump ← dictionary ← til_dict() ← Konto-objekter


    def til_dict(self):

Utfordring: Transaksjonshistorikk

  1. Gi Konto en ny attributt historikk (en liste)
  2. sett_inn() og ta_ut() legger til en linje i historikken
  3. Lag metoden vis_historikk()
  4. Få med historikken i til_dict() og ved lesing fra fil
  5. Legg til et menyvalg

Hvor mange steder måtte du endre nå — sammenlignet med del 1?

Poeng etterpå: Nesten alle endringene skjer i Konto-klassen. overfor_til() måtte ikke endres i det hele tatt, fordi den bruker ta_ut() og sett_inn(). Løsningsforslag ligger i README.md.
